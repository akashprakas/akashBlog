# P2 low-dim study: consolidating RL specialists into one policy (spec, frozen 2026-10-10; amended 2026-10-19, see §9)

Small, controlled version of the P2 capstone (plan.md §4.4b). It runs in robomimic low-dim with the official JAX
OGPO_public code. SmolVLA/LIBERO is the confirmation step, done only if this study gives a clear result.

**Claim:** a controlled comparison of consolidation strategies. No novelty claim until the §8 prior-art pass is done.

## 2. Policy and interfaces (the shared policy)

- **Network:** OGPO's MLP flow actor, plus a one-hot task ID (2-D) input.
- **Observations:** zero-padded to 53, with a per-task obs normalizer fitted on that task's demos.
  - The padding and normalization are tested by a unit check: padded Square obs must give the same normalized values in the real 23 dims.
- **Chunk interface:** a shared trunk with one action head per task.
  - Square head: 4×7. Tool Hang head: 8×7.
  - The critic for each task sees only that task's executed chunk.
  - No 8-wide Square output with masking: it would double the critic's action dim and break comparability with the published h=4 config.
- **Specialists:** both start as clones of the shared BC checkpoint. Each runs OGPO+CA on its own task with that task's official hyperparameters (h, γ, critic depth 4×512 / 5×512, start_training, success-buffer flags).
- **Teacher:** OGPO actor + best-of-8 SDE + critic argmax (OGPO's eval mode).
  - The label for a state is the **selected** chunk.
  - The actor alone (no critic) is also evaluated.

## 3. Arms

| id | arm | init | env steps |
|---|---|---|---|
| A0 | official per-task BC → OGPO, Square only (sanity reference vs the published curve) | per-task BC | official |
| A1 | shared multitask BC | — | 0 |
| A2 | specialist bank (route by task ID to the specialist) | A1 | S per task |
| A3 | offline student: task-balanced teacher rollouts (selected chunks), demos kept as a separate mixture source, flow-matching loss | A1 | S·2 + C |
| A4 | routed DAgger student: same as A3 in data mix, loss, init and steps, but labels come from the teacher on student-visited states | A1 | S·2 + C |
| A5 | joint multitask OGPO: per-task critic heads, task-balanced replay, one success buffer per task, per-task h/γ | A1 | S·2 + C |

- S is the specialist env budget per task; C is the collection budget.
- A3 and A4 use the same teacher-query budget Q. A5 uses the same total env budget as A2 + collection.

**BC stopping across two tasks (A1):**
- Stop when both tasks reach SDE best-of-8 success ≥ 45%, the official `clip_bc_threshold`, checked at `eval_interval_bc`.
- Otherwise stop at the official `bc_pi_steps` = 500k.
- Record the per-task success at the stop.

## 4. Evaluation (identical for every arm)

- Each checkpoint is reported in three modes:
  - (i) deterministic ODE;
  - (ii) best-of-8 SDE without a critic (uniform pick);
  - (iii) best-of-8 + critic argmax, for arms with a critic (A0, A2, A5).
- Students are compared to the teacher in (i) and (ii). Mode (iii) is reported only as the teacher's ceiling.
- Episodes: 64 per task per checkpoint on the 5090. Official is 32 envs × 2; we use 8 × 8 or 4 × 16 (host RAM, §6). `evaluation.py:488-491` seeds round r with `global_step + r·n_eval_envs`, so a different env/episode split gives a different seed set. Use the same split (8 × 8) for every arm; eval seeds are then the same set per task for every arm.
- Report the Wilson 95% CI per task. Per-seed results are kept; claims are made at the seed level (≥3 seeds).

## 5. Gates

| stage | gate |
|---|---|
| 2 smoke | no OOM, no sustained swap; peak VRAM / host RAM / compile time / it/s recorded → choose box |
| 3 shared BC | both tasks ≥ ~45% in mode (ii) at the stop (usable competence) |
| 4 specialists | 1 seed for debugging, then 3 seeds; mean gain over A1 in mode (iii) with CIs that don't overlap on ≥1 task (= G1) |
| 6 recovery | teacher success from saved student-failure states (robosuite `get_state`/`set_state`) > student's own (= G2) |

- Stage 4 saves the full teacher: actor, critics, normalizers, and the replay and success buffers.

## 6. Budget (stage 2 measured on the 5090, 2026-10-10; logs in `smoke/results/gpu_*` on that box)

- **Measured (user-reported, `gpu_smoke.sh`, all 4 stages exit 0), with `jax_frac` 0.45 and 4 eval envs:**
  - BC: Square ~717–813 it/s, Tool Hang ~693 it/s.
  - Online: Square ~33–35 it/s, Tool Hang ~29–40 it/s. These rates came from short runs (6k / 4k steps) with tiny evals (4 envs × 1 episode). They are not yet the rate with the full 64-episode eval.
  - Peak VRAM 15.2 GB, which is the preallocation at `jax_frac` 0.45.
  - Peak host RSS: 17.1 GB (Square), 17.0 GB (Tool Hang).
  - Checkpoint: 263/263 leaves identical; ODE, SDE and BoN actions bitwise equal after reload.
- **Official schedules:**
  - BC: 500k steps, or stop early at 45% SDE success. At ~750 it/s that is ≤ 12 min.
  - Online: Square 2M steps, Tool Hang 2M in `toolhang.sh` (3M in paper Table 5).
- **Per-seed online time at the measured rates, before eval overhead:** Square 2M ≈ 16 h; Tool Hang 2M ≈ 14–19 h (3M ≈ 21–29 h).
- **Core runs:** A0 ×1 + specialists 2×3 + A5 ×3 = **10 RL runs**.
  - A5 trains both tasks, so ≈ 2× one specialist.
  - Serial total ≈ 16 + 3·16 + 3·17 + 3·33 ≈ 210 h ≈ 9 days of GPU, plus eval overhead and students.
- **Runs are serial:** 17 GB host RSS per run on a ~30 GB host means two runs can't share the box.
- **First pass at 1M online steps** (decided 2026-10-10): half the official 2M, Square ≈ 8 h/seed before eval. The LR schedules don't read online_steps, so a 1M run is exactly the first half of a 2M run; relaunching with the same tag and `--online_steps=2000000` resumes from the rolling backup. Launcher: `runs/run_ogpo.sh`.
- **Eval workers:** use 4 (at most 8), not 32. The 64 episodes of §4 are then 4 envs × 16 or 8 × 8 sequential rounds. Measure the eval wall time on the first long run (A0).

2. JAX sees the GPU; MuJoCo EGL renders/steps; both datasets load through `envs/robomimic_utils.get_dataset`.

   - peak VRAM;
   - peak host RAM;
   - first-step compile time;
   - steady-state it/s for BC and online;
   - checkpoint save → reload → the same eval actions.
4. Tool Hang: env construction and dataset load, plus a few hundred online steps for it/s (its 1000-step episodes are slower).
5. Check `env.sim.get_state()` / `set_state` through OGPO's wrapper (needed for G2).

## 8. Prior-art pass (bounded, ~2 h, before any claim)

- Papers: Policy Distillation (Rusu 2015), Actor-Mimic (Parisotto 2015), **Distilling Policy Distillation (Czarnecki
  2019; compares teacher- vs student-driven distillation directly, the closest to A3 vs A4)**, Kickstarting (Schmitt 2018), Distral (Teh 2017), Divide-and-Conquer RL (Ghosh 2017), Learning by Cheating (Chen 2019), RLDG 2412.09858, CPC 2601.22475, RLinf-VLA 2510.06710, 2609.28838.
- For each, one line: what it distills, from what teacher, whether it compares offline vs on-policy labels at a matched budget, and whether it includes joint RL at a matched env budget.

## 13. Amendment 2026-10-22 (Stage 6 / G2 recovery results, seed 1)

The text above is unchanged. Where §13 conflicts with it, §13 governs from this date. Sources: `runs/results/stage6/recovery_{square,toolhang}.json` (late branch points) and `runs/results/stage6_early/recovery_{square,toolhang}.json` (early branch points); script `stage6_recovery.py`, CPU, 64 episodes per task, seeds 10000 to 10063.

**What was measured.** The A1@230k student ran from reset on the 64 seeds with a simulator snapshot saved at fixed steps. Episodes that never reached success are "failed episodes" (Square 25, Tool Hang 32). From each snapshot of a failed episode, the simulator was rewound twice: branch A, the student drives to the end of the episode (fresh noise); branch B, the teacher drives to the end. The teacher is the plain A2 actor in single-sample SDE mode (EMA weights), **not** the critic-selected best-of-8 labeller of A3/A4. Nothing is trained in this stage.

**What a "failure state" is.** The only thing known about a snapshot is how its episode ended. A "failure state" is a state taken from an episode that failed later. It is not known to be a bad state. At early steps most are still fine, so the student's own "rescue" rate is inflated by states from which a different noise draw simply succeeds. It does not measure recovery from a mistake.

Student from reset: 39/64 (Square), 32/64 (Tool Hang). Teacher from reset: 54/64 (84.4%) and 56/64 (87.5%). Branch steps are rounded up to the next chunk boundary (Square chunks 4 steps, Tool Hang 8).

**Findings (one seed, one A1 checkpoint, one teacher mode)**
1. The teacher does better than the student from states on failing trajectories, and the advantage is largest at early snapshots and fades with later ones (Square: +40 at step 20, +4 at step 300; Tool Hang: +37.5 at step 20, +28 at step 100, 0 at step 500).
2. Four of the thirteen branch points reach one-sided p < 0.05 (Square 20; Tool Hang 20, 70, 100); none of the late points do. Thirteen tests were run and no multiple-comparison correction was applied. The consistency of the Tool Hang gain across steps 20 to 100 (+22 to +38 points) is stronger evidence than any single p-value.
3. Late snapshots (Square 300; Tool Hang 500 and 750) are mostly unrecoverable for both policies and say little about label quality.

**G2.** The SPEC-literal form (teacher rescues > student rescues) holds at 11 of 13 branch points (the exceptions are Tool Hang 500, a tie at 3 and 3, and Tool Hang 750, 0 against 1). The paired significance test holds at the points above. G2 is therefore supported at seed 1, mainly at early snapshots, and remains provisional until three seeds exist (§10).

**What G2 does not show**
- It does not show A4's labels are good. In G2 the teacher drives the whole remaining episode; in A4 the student drives and the teacher labels one chunk at a time.
- The teacher's rescue rate (44 to 72% at early steps) is below its reset rate (84 to 88%), but the failure seeds were selected because the student failed on them, so this does not indicate poor labels.
- It does not show the student was already in a bad state at the snapshot, or when the student started going wrong.
- State restore is approximate, not bit-exact (`smoke/SMOKE_RESULT.md` item 7); observations after a restore are stale by about 1e-3.
- The plain-actor teacher is not the critic-selected best-of-8 chunk. A best-of-8 teacher may rescue more, especially on Square, where best-of-8 added about 8 points over single SDE (Tool Hang: none).

**Not done**
- A test closer to A4's labels (student drives, teacher labels each visited state, measure how often and how much its chunk differs from the student's).
- Labelling snapshots as healthy or doomed (e.g. whether the teacher can finish from them).
